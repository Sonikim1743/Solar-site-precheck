# 地番選択と住所検索の追加修正

## 症状と再現

公開地図の参考領域を2区域選び「選択完了 → 3D」を押すと、外周に接触する中抜きのエラーで適用できない事例を調査した。試用版のUI整理とは別の、従来からある図形結合経路で発生する。

保存された独立取得の公開参考図形は、各区域の検証と結合に成功した。一方、現在の公開AMX PMTilesをアプリと同じ `PmtilesSource → TileCache → resolveMapParcelSelection → measureParcelReview` で読むと、同じエラーを再現した。歴史的な操作時のブラウザー内部図形は保存されていないため、当時とのバイト単位の同一性は確認していない。候補地の座標・案件記録・実資料・画面画像は公開ソースに含めない。

タイル断片の結合で片側だけに追加された共有辺の頂点があり、各区域を非線形の等積投影へ個別に変換してから合併すると、共有辺の扱いが異なり、極めて細い接触中抜きが生じる。これは3D描画やDEM取得の前に起きる。

## 修正の範囲

- 複数の地図参考領域で、計算後にこの外周・中抜きの検証エラーが出た場合に限り、参考領域同士を共有座標上で先に合併してから、従来のメートル単位の面積計算・指定境界・除外を適用し直す。再計算後も同じ厳格な図形検証を通す。
- 穴を削除する処理、バッファー、スナップ、簡略化、頂点上限の緩和は加えない。入力として不正な穴は従来どおり拒否する。元の個別図形と記録は変更しない。
- 従来の計算結果が有効なら、その図形・面積・地形識別値をそのまま返す。既存の正常な保存地形を別の図形として扱わない。原本ファイルだけの検討経路は変更しない。
- 住所検索は名称の一致だけを判別し、地番精度を認定しない。1候補でも入力名と返却名が異なる場合は自動移動しない。候補には「地番位置は未確認」を表示し、明示的に選んだ後も注意を残す。入力した地番を返却された地域名で上書きしない。名称一致の1候補と直接の座標入力は従来の簡単な操作を保つ。

今回確認した参考領域の再計算前後の面積差は約0.000063m²。これは今回の計算差であり、原本境界・地図位置・測量精度の保証ではない。タイル化・量子化による境界の差や欠落という既存の制約は残る。

## 試用と検証

同じWindows PCで `http://127.0.0.1:5190/` を開く。停止後は `RUN_PARCEL_PREVIEW.cmd` で再起動できる。ビルド済みdistとNodeが必要。総合チェック試用版の5187、従来のローカル版、公開サイトとは別のオリジンで、ブラウザーの保存内容を共有しない。外部からアクセスできる公開URLではない。

Windows / Node 24.22.1 / pnpm 11.25.0で全687件、ビルド、CSP、ブラウザー同梱資産、リリースメタデータ検査が通過。匿名の合成図形で、修正前の同じ接触中抜きエラー、修正後の両順序での結合、実際の穴・分離・隙間・境界・除外の保持、不正入力の拒否、既存の正常結果の完全一致を確認した。住所検索の名称不一致・全角数字・空白・欠損名称も検証した。

Edgeで実際の公開タイルを表示し、報告された2区域を順に選択し、「適用済み2区域」、DEM取得、3D表示と回転まで成功。CSS幅1024pxと375pxで横のはみ出しなし。375pxでも回転、住所候補の注意と自動移動抑止、計算画面との往復後の選択・地形・視点保持を確認した。検索だけで移動しなかった場合、取得済み3Dの識別値も変わらない。画像と試験記録はGit対象外の `outputs/qa/` にのみ保存した。

現場測量との精度照合、法的境界・規制の確定、PDF全体、Mac/Safari、実機タッチ、ブラウザーでの記録ファイル読込・復元は今回の検証対象外。既存DEM未提供タイルの404と大きいJSチャンクの警告は残る。

この修正は `fix/parcel-hole-union` で既存試用版から分離した。総合チェック試用版と規制PRは変更せず、mainへのマージ・運用配布・公開プレビューの作成は行わない。
