# 地図注意・表示切替・フェンス・シンプル画面の検証

基準は公開main `0db616b8c96ec3c927f66b5ad5577cae1db13c7d`（製品ソース `ec28dd6`）。別worktreeの `codex/parcel-notice-popover-20261016` で作業した。今回の変更はローカル検証用で、push・配布パッケージ作成・公開デプロイは行っていない。既存利用者のタブ・保存領域は操作せず、一時Edgeと合成資料を使用した。

## 実装範囲

- 地番選択の短い操作案内の直後にⓘを置き、公開2024境界の制限・黄色線の確認を既存のモーダルダイアログに移した。同一IDの隣接断片を結合した説明は、その通常成功メッセージの時だけ同じダイアログに入る。取得失敗・未確認の連続境界・限定選択の警告は画面に残す。作図中の案内も保持する。
- 地図の⋯内は、既存の地名レイヤー状態を使う単一の「地名 ON/OFF」ボタンにした。地番表示とは独立。標準地図そのものに含まれる地名は消せないという説明を保持する。Escapeと外側操作でメニューを閉じられる。
- 「3D地番 ON/OFF」の隣に「フェンス ON/OFF」を置き、詳細条件内の重複チェックボックスを除いた。既存の `terrainPreview.fence` を更新し、同じ3D・1枚図面・報告書の描画経路を使う。配置の再計算や新しい状態は追加していない。
- 「シンプル／詳細」を小型の2分割スイッチにした。既存の切替処理と状態を使い、選択背景だけを160msで移動する。左右矢印・Home・End・Enter・Space、フォーカス表示、`aria-pressed`、reduced-motionに対応する。
- シンプル画面のメイン幅を詳細と同じ上限1440pxにし、地図高の440/340px専用指定を除いた。画面内の対話型3Dだけ最大幅を解放した。Leafletのコンテナ変化をResizeObserverで通知し、モード切替後も実際の寸法・表示中心を一致させる。高さ700px以下の携帯画面では両モードとも地図を `clamp(300px,58svh,420px)` に制限する。

シンプル画面が小さく見える主因はコンテナ幅・地図高だった。変更前のデスクトップ3Dのカメラ値・表示枠は詳細と同じで、モードによる数値ズーム低下は再現しなかった。変更後もカメラの方位・俯角・拡大率を操作して拡大する実装にはしていない。報告書・印刷用の固定視点や出力レイアウトは対象外。

通常注意文を移したのは地図選択UIだけで、`TerrainAreaReport`・PDFの注意／出典／DEMの制限は変更していない。統計・元の境界・高さ・勾配・実寸・配置計算も変更していない。

## 初回表示でレポートが開く件（調査のみ）

新規保存領域のルートURLでは、レポートのdetailsに `open` はなく、実画面でも閉じている。合成の保存済み候補地がある場合も同じ。ブラウザ保存のdraftにはページ・レポート種別・折りたたみの開閉・最終表示位置の保存項目がない。`reportView='summary'` は内容の種類で、開閉指定ではない。PWAの開始URLも `/`。

`#report-section` への直接アクセスは既存仕様によりレポートを開く。メニューでレポートを開くとそのhashを書き、同URLの再読込でも開く。一度開いた同じDOMで候補地マップへ戻った場合、URLは `#site-select` に変わるがレポートdetailsはその場で開いた状態を維持する。そのURLを再読込すると閉じる。公開実Appの一時ブラウザで新規・保存済み・直接URL・メニュー・再読込の11条件を確認し、pageerrorは0だった。閉じた内容にbounding rectが返る場合があるため、実表示は `checkVisibility()` とdetails高も確認した。

したがって「初回は常にレポートを開く」「localStorageが最後のレポート画面を復元する」という処理はない。利用者が見た元のURLやブラウザ復元条件は未確定。今回、初期表示やレポートの開閉挙動は変更していない。

## 複数地番の範囲選択（調査のみ）

実装可能。ただし現在のpoint queryの許容半径を広げる方法ではPolygonを矩形選択できない。PMTilesのz16タイルを矩形の範囲で列挙し、ID・地番・地図名・区域・座標系で重複排除してから、既存の隣接断片の復元と検証を通す必要がある。選択に使うのは全体の既知形状で、選択矩形による切抜き・重心だけの判定・地番文字だけの結合は避ける。表示用の3D地番スナップショットは上限・省略・ID欠如があり選択元に使えない。

推奨は明示的な「範囲で選択」モード。PCは矩形ドラッグ、携帯は対角2点指定、Escapeで中止。モード中だけpan/boxZoomを止め、末尾のclickを抑止する。最初の小規模実装をPCも対角2点にすると、ドラッグとの競合を減らせる。同じ幾何判定を使えば選択精度は変わらない。

既定は「全体が枠内」、任意で「枠と一部重なる」。取得後に件数・黄色境界・未復元／上限到達をプレビューし、現在の「選択完了 → 3D」で適用する。全取得成功前に現在の選択を壊さず、部分取得を黙って適用しない。共有タイルキャッシュ・並列数・総タイル／頂点／候補件数・キャンセルを設け、既存の100区域上限と連携する。現在の隣接探索は1地番25タイル上限で、PMTilesに未収録の遠隔分離領域や原本全筆は保証できない。原本全筆が必要なら既存XML/GeoJSON読込が適する。

タイルのクリッピング・単純化や同ID断片の扱いは [Mapbox Vector Tile仕様](https://mapbox.github.io/vector-tile-spec/) と [PMTiles公式資料](https://docs.protomaps.com/pmtiles/) も参照した。範囲選択の製品コードは今回追加していない。
