## 우선 진행할 과제
- **저장·재개 신뢰도:** 여러 탭의 저장 충돌과 환경 간 범위 식별을 먼저 재현하고 해결한다. 파일 열기 전 범위 면적·지형 유무·취득일을 확인할 수 있게 하고, 저장 성공·실패·최근 복구본을 구분한다. 실제 범위·제외·격자·자료가 바뀐 기록은 잘못 재사용하지 않아야 한다.
- **안내의 실제 동선 일치:** 접힘의 열림/닫힘 문구, 지평선과범위지형의 이름, 자료 저장 위치를 맞춘다. 접힌 활용 예시에 범위→등고선·3D→A3 PDF→기록→SolarPro/CAD 인계의 짧은 일본어 절차를 추가한다. 새 상시 설명과 메뉴를 늘리지 않는다.
- **인계 자료 실증:** 범위 선택 → 등고선·경사 → 평면/3D → A3 두 쪽 PDF → schema 3 기록 재개를 실제 안건으로 확인한다. PDF·JSON·필요한 지평선CSV·미확인 항목이 같은 후보지와범위를 가리켜야 한다. 구현·검증·패키지·GitHub·공개 배포를 서로 다른 완료 단계로 기록한다.
- **실제 안건 세 건 파일럿:** 경계가 확인되는 평탄한 토지, 경사와 접도 검토가 필요한 토지, 제외·결측·자료 혼합이 있는 토지로 사용 흐름을 점검한다. 각 안건은 비공개 공간에 두고, 시작부터 보고서 전달까지의 시간과 수동 수정 시간, 자료 출처·기준일·미확인 조건, 처음 읽는 담당자가 범위와 경사를 설명할 수 있는지, 다른 담당자에게 기록을 넘겨 같은 결과로 재개할 수 있는지를 기록한다. 좋은 그림의 수보다 검토 시간과 전달 품질을 평가한다.
- **수익화 검증:** 유료 검토서·템플릿의 수요, 제공 범위, 작성 시간, 검수 책임, 반복 구매 의향과 지불 의향은 미검증이다. 세 건의 파일럿 결과와 업무 이용자의 반응을 보고 상품화 범위를 정한다. 수익·시공 가능·접속 승인을 보장하는 판매 표현을 사용하지 않는다.

## 이후의 운영
- **Mac 개발 인수:** `MAC_OPENCLAW_START_KO.md`에 따라 받은 브랜치·커밋·의존성·화면과 실제 작업 폴더를 확인한다. 코드 수정은 Mac 중심이 기본이며 이번 Windows 코드 작업은 사용자 명시 승인에 따른 예외다. Mac 실기 검증은 별도로 남긴다.
- **배포 재현성:** GitHub CI와 Cloudflare 배포 절차를 확인한다. GitHub 갱신을 공개 배포 완료로 취급하지 않는다.
- **여러 탭의 기록 보존:** 같은 실행 주소의 여러 탭에서 새로고침 후 직전 선택이 복원되지 않는 현상이 관찰됐다. 원인을 확정하고 최초 로딩의 불필요한 저장, 탭별 복구본, 저장 충돌 감지와 실패 안내를 검증한다. 화면 크기 개선만으로 이 문제가 해결됐다고 기록하지 않는다.
